# 产品需求文档 (PRD) - 极简咖啡摊点单库存系统

## 代码页面放置位置 src\views\business

## 数据放置位置 mock\business， 依然采用“本地 JSON 文件 + 浏览器存储”的双层方案





## 1. 项目概述
### 1.1 项目背景
个人经营的小型咖啡摊位，仅需 PC 端（Web 浏览器）进行日常经营管理和收银。系统需替代传统的纸笔记录，实现数字化点单、自动库存扣减及简单的财务统计。
### 1.2 核心目标
1.  **极速点单**：实现“听单-点击-出号”的快速操作流程。
2.  **库存一体化**：商品即库存单位，卖一杯扣一杯，无需配置复杂的原料配方。
3.  **极简架构**：去除会员、支付、配方等非必要功能，专注于“收银+库存”核心闭环。
### 1.3 用户角色
*   **管理员（老板）**：拥有所有权限，负责点单、制作、补货、查账。
---
## 2. 页面结构与功能概览
系统共分为 **3 个核心页面**：
1.  **收银台**：日常营业使用，高频操作，负责点单、出号、状态流转。
2.  **后台管理**：低频操作，负责商品上下架、价格设置、库存补货、预警设置。
3.  **数据统计**：复盘使用，负责查看营收、历史订单、销量排行。
---
## 3. 详细功能需求
### 3.1 页面一：收银台
**用途**：全天候打开，核心工作台。
#### A. 布局设计
建议采用 **“左中右”** 或 **“上中下”** 布局，确保操作路径最短。
#### B. 功能模块
**1. 商品选择区（左侧/上部）**
*   **分类导航**：横向 Tab 按钮（如：咖啡、奶茶、小吃），点击切换商品列表。
*   **商品网格**：
    *   以大卡片/按钮形式展示 **“上架”** 状态的商品。
    *   显示信息：商品名称、售价。
    *   **交互**：点击商品卡片 -> 自动添加至右侧“当前订单”区。
    **2. 当前订单区（右侧/中部）**
*   **临时订单列表**：
    *   显示本次点单的商品列表。
    *   支持修改数量（+ / -）、删除商品。
    *   显示当前订单总金额。
*   **备注功能**：
    *   提供快捷标签（少糖、去冰、热饮）或输入框，用于记录顾客特殊需求。
*   **排队号显示**：
    *   大号字体显示“当前排队号”（如：A006）。
    **3. 操作按钮区（底部/右侧）**
*   **【确认下单】**：
    *   生成正式订单。
    *   生成排队号（格式：字母+数字，每日重置）。
    *   **核心逻辑**：扣减对应商品的库存数量。
    *   弹窗/提示：“下单成功！当前排队号：A006”。
*   **【挂单】**（可选）：
    *   暂存当前未支付的订单，方便处理下一个顾客。
    **4. 制作队列区（独立区域/侧边栏）**
*   **待处理列表**：
    *   展示状态为“待制作”、“制作中”的订单。
    *   卡片信息：排队号、商品名、备注、下单时间。
*   **操作按钮**：
    *   【出餐完成】：点击后，订单状态变更为“已完成”，从列表消失或变灰移至历史。
    *   **【作废】**：点击后，订单取消。**核心逻辑**：系统自动回滚库存（把刚才扣掉的库存加回去）。
---
### 3.2 页面二：后台管理
**用途**：每日进货时、上新品时使用。
**布局**：建议使用 **Tab 页签** 切换以下模块。
#### A. 商品与库存管理（核心 Tab）
这是唯一的数据管理入口，商品信息和库存数量合二为一。
**1. 列表字段**
*   商品名称
*   分类
*   售价
*   **当前库存**（核心字段，醒目显示）
*   状态（上架/下架）
*   操作栏
**2. 功能按钮**
*   **【入库】**：
    *   点击弹出输入框：输入入库数量。
    *   逻辑：`当前库存 + 入库数量`。
    *   场景：每天进货回来，点击此按钮增加库存。
*   **【新增商品】**：
    *   填写：名称、分类、售价、初始库存。
*   **【编辑】**：修改名称、售价、分类。
*   **【上架/下架】**：控制该商品是否在“收银台”显示。
**3. 库存预警（辅助功能）**
*   列表中，当“当前库存”低于某个预设值（如 5）时，该行标红显示。
#### B. 分类管理（辅助 Tab）
*   简单的增删改查，用于管理商品分类（如：美式、拿铁、特调）。
---
### 3.3 页面三：数据统计
**用途**：每日收摊后查看。
**1. 核心指标卡片**
*   **今日营收**（元）
*   **今日订单**（单）
*   **今日出杯**（杯）
**2. 历史订单列表**
*   支持按日期筛选。
*   显示字段：排队号、下单时间、商品明细、总金额、状态（已完成/已作废）。
*   点击可查看订单详情。
**3. 热销排行**
*   展示销量 Top 5 的商品名称及数量。
---
## 4. 数据模型设计
系统仅需 2 张核心业务表，逻辑极简。
### 4.1 商品表
*说明：既是商品，也是库存单位。*
*   `id`: 主键
*   `name`: 商品名称 (如: 冰拿铁)
*   `category`: 分类 (如: 咖啡)
*   `price`: 售价 (单位: 元)
*   `stock`: **当前库存数量** (核心字段)
*   `status`: 状态 (1: 上架, 0: 下架)
*   `image_url`: 图片地址 (可选, 可用占位符)
### 4.2 订单表
*   `id`: 主键
*   `order_no`: 排队号 (如: A001)
*   `total_amount`: 订单总金额
*   `status`: 状态 (0: 待制作, 1: 已完成, 2: 已作废)
*   `remark`: 备注 (如: 少糖、去冰)
*   `create_time`: 下单时间
### 4.3 订单详情表 (order_items)
*   `id`: 主键
*   `order_id`: 关联订单
*   `product_name`: 商品名快照
*   `product_price`: 商品单价快照
*   `quantity`: 数量
---
## 5. 核心业务逻辑（开发必读）
### 5.1 下单扣库存逻辑
当用户在【收银台】点击【确认下单】时：
1.  开启数据库事务。
2.  遍历订单中的商品列表。
3.  执行 SQL：`UPDATE product SET stock = stock - 数量 WHERE id = 商品ID`。
4.  生成订单记录，写入 `orders` 和 `order_items` 表。
5.  提交事务。
### 5.2 作废回滚库存逻辑
当用户在【收银台】点击【作废】时：
1.  开启数据库事务。
2.  查询该订单下的所有商品及数量。
3.  执行 SQL：`UPDATE product SET stock = stock + 数量 WHERE id = 商品ID`。
4.  更新订单状态为“已作废”。
5.  提交事务。
### 5.3 排队号生成规则
*   格式：字母 + 3位数字（如 A001）。
*   规则：按日期分隔，每天从 001 开始递增。
*   实现：查询当天最大号 + 1。

### 6.1 UI 交互
*   **风格**：简洁、清晰、高对比度（户外摊位可能有强光）。

## 7. 场景确认

#### 这里有 **5 个核心场景**，请你逐个确认是否符合你的心理预期：
#### 场景一：早高峰出杯（核心流程）
**情境**：
早上出摊，你预估今天能卖 50 杯美式、30 杯拿铁。
顾客 A 来了：“老板，一杯冰美式。”
顾客 B 跟着说：“我要一杯热拿铁，少糖。”
**操作流程**：

1.  你在【后台管理】快速设置：美式库存 50，拿铁库存 30。
2.  切换到【收银台】。
3.  点击“美式(冰)”按钮 -> 点击【确认下单】。
    *   *系统动作：生成排队号 A001，美式库存自动变为 49。*
4.  点击“拿铁(热)”按钮 -> 点击备注标签“少糖” -> 点击【确认下单】。
    *   *系统动作：生成排队号 A002，拿铁库存自动变为 29。*
    **👉 确认点：**
*   **关于规格**：你是希望“冰美式”和“热美式”是**两个独立的按钮**（各自管各自的库存，比如冰美式剩10，热美式剩5）？
*   只有一个“美式”按钮，点进去再选冷热（库存共用，卖出一杯扣一杯，不分冷热）
    *   *建议：小摊位选第一种（独立按钮），库存管理最直观，不用思考冷热比例。*
---
#### 场景二：库存不足预警（边界情况）
**情境**：
生意太好，拿铁只剩下 **1 杯** 的原料了。
这时候进来一位顾客要买 **2 杯拿铁**。
**操作流程**：
1.  你在【收银台】点击“拿铁”两次。
2.  点击【确认下单】时。
    *   **系统反应 A（建议）**：弹出红色警告弹窗——“库存不足！当前拿铁仅剩 1 杯”。下单失败。
    *   **系统反应 B（宽松）**：允许下单，但库存变成 -1，并在订单上标红提醒你“超卖”。
    **👉 确认点：**
*   系统是 **“严格阻断”**（没货就点不了，防止超卖）
---
#### 场景三：顾客临时反悔（作废回滚）
**情境**：
刚刚排队号 A003 的顾客（买了 1 杯拿铁），突然说“不想等了，退了吧”。
**操作流程**：
1.  你在【收银台】右侧的“制作队列”中，找到 A003 号订单。
2.  点击该订单下的【作废】按钮。
3.  系统弹出确认框：“确认作废？库存将退回”。
4.  你点击确认。
    *   *系统动作：订单 A003 状态变为“已作废”，拿铁库存自动 +1（从 29 变回 30）。*
    **👉 确认点：**
* 这个“一键回滚库存”的功能对你重要吗？（这是数字化管理最大的便利之一，不用你脑子里记着把豆子加回去）。

  重要，直接回滚回去
---
#### 场景四：中途补货（动态库存）
**情境**：
下午 2 点，你发现拿铁原料用光了，正好供应商送来了新的一箱牛奶/豆子（预估能再做 20 杯）。
**操作流程**：
1.  你无需退出收银界面，直接点击顶部菜单的【后台管理】。
2.  在商品列表找到“拿铁”，点击旁边的【入库】按钮。
3.  输入数字：20。
4.  点击保存。
    *   *系统动作：拿铁库存瞬间更新（比如从 2 变成 22）。*
5.  你立刻切回【收银台】，继续卖拿铁。
**👉 确认点：**
* 这种“切页入库”的方式，你的操作习惯能接受吗？（还是希望在收银台就能有个快捷入库入口？）

  能接受，希望收银台有快捷入库按钮
---
#### 场景五：打烊复盘（数据统计）
**情境**：
晚上收摊，你想知道今天赚了多少钱，以及明天该备多少货。
**操作流程**：
1.  点击【数据统计】页面。
2.  页面顶部显示：
    *   今日营收：888 元
    *   今日出杯：45 杯
3.  页面下方显示“热销排行”：
    *   第一名：冰拿铁（卖出 20 杯）
    *   第二名：美式（卖出 15 杯）
4.  你看了一眼库存：
    *   美式还剩 5 杯（明天可能要多备点）。
    *   拿铁剩 0 杯（卖光了，明天要补货）。
